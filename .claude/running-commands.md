# Running commands: background

Moved out of `CLAUDE.md` so it is read only when needed. `CLAUDE.md` keeps the summary and the hard rules.

- Node comes from nvm (`.nvmrc`) and pnpm from corepack (`packageManager` in `package.json`); there's no system Node. Run node/pnpm through `.claude/scripts/agent-run.sh <command>` (e.g. `.claude/scripts/agent-run.sh pnpm check`). It runs from the repo root (so pass absolute paths for anything outside it, e.g. `npm i --prefix <scratchpad> …`), loads nvm from `$NVM_DIR` (default `~/.nvm`), Arch's `/usr/share/nvm`, or Homebrew's `nvm`, runs `nvm use`, and falls back to a zsh login shell if none of those work. Both of the user's machines are covered: Linux (CachyOS; fish is the interactive shell, nvm is the pacman package, agent shells run zsh) and a Mac.
- Staying on Node and pnpm, not Bun: a spike (2026-09-29) found Bun can't read pnpm 12's lockfile, `nuxt build` ran slower under Bun than Node on the same packages (~43 s vs ~32 s), and the built server showed no runtime gain for this database-bound app; Vercel's Bun runtime is also still beta.
- pnpm keeps its default symlinked `node_modules`. The hoisted layout (`nodeLinker: hoisted`) cut local builds from ~55 s to ~32 s, but Vercel's install then fails ("the installed pnpm wrapper is missing" while its pnpm switches to the `packageManager` version), so it was dropped. An untried fix is Vercel's `ENABLE_EXPERIMENTAL_COREPACK=1`; the ESLint rule `import/no-extraneous-dependencies` (on since #45, checks `package.json`, not `node_modules`) would keep catching undeclared imports under a hoisted layout.
- Cloud sessions: a fresh clone has no `.env.local` (it's gitignored and holds live secrets), so anything that needs the database (dev server, `pnpm db:*`, `pnpm admin:set`, API checks) won't work until the environment provides `DATABASE_URL` and `BETTER_AUTH_SECRET`; typecheck, lint, tests, and template compilation work without them.
- Browser checks: on Linux, Chromium's headless shell is installed in Playwright's cache (`~/.cache/ms-playwright`; on a Mac the cache would be `~/Library/Caches/ms-playwright`), which persists across sessions. The Mac uses Google Chrome instead: launch with `channel: "chrome"`. Install `playwright-core` in the session's scratchpad (`.claude/scripts/agent-run.sh npm i --prefix <scratchpad> playwright-core`), run scripts with `NODE_PATH=<scratchpad>/node_modules`, and `chromium.launch()` finds the cached browser; if a newer `playwright-core` wants another browser revision, run `npx playwright-core install chromium-headless-shell` again. Scratchpad scripts reach project packages (e.g. `pg`) with `createRequire("<repo>/package.json")`. Use `withSmokeUser` from `.claude/scripts/smoke-session.mjs` for throwaway `claude-smoke-*@example.invalid` users: it registers, signs in, hands you the session cookie, and deletes the user afterwards (run with `node --env-file=.env.local`); delete only users you created. Listen for console errors: Vue hydration mismatches only show there. The helper deletes the user but **not resources it owns**, so delete what you create through the API before its callback ends. To look at your real resources read-only instead, send your API key: `.env.local`'s `SOUL_TABLETOP_API_KEY` in an `x-api-key` header through Playwright's `extraHTTPHeaders` shows pages as you, with no throwaway user.
- Checking UI work: `pnpm check` and `pnpm check:templates`, then a dev server on a spare port (the user's runs on 3000 or 3001; check with `lsof -iTCP -sTCP:LISTEN -P | grep node`) started from the worktree with `.claude/scripts/agent-run.sh pnpm nuxt dev --dotenv <main checkout>/.env.local --port 3005`, and Playwright screenshots of signed-out pages and of signed-in pages via `withSmokeUser`. Start it with Bash's `run_in_background` and the longest `timeout` (7200000 ms): the 30-minute default stops it mid-run, and a smoke user whose callback was cut off is left behind with its resources (delete those rows, then the user). Stop the dev server you started. On a fresh dev server the first load of a page can fail with Vite's "504 Outdated Optimize Dep" plus a hydration warning; reload, it's not the app. After adding components or `app/utils` files, the server can serve stale auto-imports (hydration warnings or "x is not a function"); restart it.
- A Vercel preview failing with `FUNCTION_INVOCATION_FAILED` while production works, with no matching log lines (2026-10-06, on two branches at once): it was a bad deployment, not the code. `vercel redeploy <preview URL>` fixed it. Check the same build locally first (`pnpm build`, then `node .output/server/index.mjs`). Previews sit behind Vercel Authentication: `vercel curl <url>` reaches them, and API keys get a 401.
- On the Mac, `.env.local` names the user's API key `SOUL_API_KEY` (not `SOUL_TABLETOP_API_KEY`): pass it on as `SOUL_TABLETOP_API_KEY` to `test-sheet.mjs` without printing it (found 2026-10-06).
- Test sheets for the user (user, 2026-10-06): when a PR adds or changes a Sheet feature, create a test setup in the user's own account for them to try on the PR's Vercel preview: a system named `Test: <feature>`, a content type, a sheet using the feature, and a character, with `.claude/scripts/test-sheet.mjs create <spec.mjs>` (a spec exports `markup`, `schema`, `data`, `name`; see the script's header), which uses `SOUL_TABLETOP_API_KEY` (never SQL). Run it against a dev server on the PR's branch, since production's code may reject the new markup and Vercel previews refuse API keys; the database is shared, so the preview shows them. Browser checks with a throwaway user can import its `createTestSheet` with `withSmokeUser`'s `request`. Put the `delete …` line it prints in `.claude/HANDOFF.md`, and run it right after the PR merges, so nothing is left behind.
- Dev servers for the user (user, 2026-10-06): when a PR is ready for them to test, leave a dev server running on the PR's branch (from its worktree, on a spare port like 3005, started as above) and give them its URL and the test page, so they can try it while Vercel builds the preview. Keep it running until they're done or the PR merges; stop it then.
- The database was reset on 2026-10-05 (all users and API keys deleted). A machine whose `.env.local` holds an API key from before then (`SOUL_TABLETOP_API_KEY`, see the README) gets 401s: create a new key on `/profile` and replace it.

## Moved from CLAUDE.md

- pnpm enforces a minimum release age (`minimumReleaseAge`): when `pnpm add` picks a version newer than that, it appends `minimumReleaseAgeExclude` entries to `pnpm-workspace.yaml` on its own. Don't keep those silently, since they bypass a supply-chain check: pick an older version that fits (e.g. `pnpm add pkg@^1.2.3` matching what's installed), or ask the user.
- Verify with `.claude/scripts/agent-run.sh pnpm check`: typecheck, lint, and test run in parallel (what CI runs) and print one line each, with output only for failures; `pnpm check typecheck lint` runs a subset and `pnpm check format:check` adds Prettier (off by default; the user formats code themselves). While iterating, `eslint <files>` and `vitest run <file>` are quicker than the full run; do the full check once at the end. **Don't run `pnpm format`** — the user formats code themselves. `pnpm test` runs vitest over `shared/**/*.test.ts` and `server/**/*.test.ts`. `RUN_DB_TESTS=1 pnpm vitest run server/utils/resource-access-sql.db.test.ts` also runs the real SQL list rules against the database (throwaway rows, deleted afterwards); it's skipped otherwise.
- Local env vars are in `.env.local` (Vercel's convention; a plain `.env` is not read): the Nuxt scripts pass `--dotenv .env.local` and `drizzle.config.ts` loads it. Its `DATABASE_URL` contains `&`, so don't `source` it; use `node --env-file=.env.local` for ad-hoc scripts. Never move, rename, or delete it (or `.env`) in tests; the files aren't recoverable from git.
- Typecheck and lint don't catch broken template structure (e.g. a missing closing tag). After template edits, run `.claude/scripts/agent-run.sh pnpm check:templates` (compiles the `.vue` files changed since `origin/main` or the ones you name; works for pages behind auth), or request a public page from the dev server (a 500 body includes the Vite compile error; auth pages just 302 without compiling). The user often has `pnpm dev` running already — check `lsof -iTCP -sTCP:LISTEN -P | grep node` for its port (3000 or 3001) before starting another, and never kill a dev server you didn't start.
- The remote is HTTPS (`https://github.com/lucyawrey/soultabletop.git`), authenticated through the GitHub CLI, so git works from agent shells that can't reach the user's SSH agent. Per machine: install `gh`, `gh auth login`, `gh auth setup-git`, `gh config set -h github.com git_protocol https`, and `git remote set-url origin` to the HTTPS URL if the clone uses SSH. Use `gh` for PRs.
