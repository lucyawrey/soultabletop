# Improvements

- **Remove `BASE_URL` entirely (also fixes login on the Vercel deployment).** Login on Vercel fails, most likely because `BASE_URL` was copied from the local `.env` as `http://localhost:3000`, so Better Auth treats the site as living on localhost and rejects sign-ins from the Vercel domain as an untrusted origin (confirm: sign-in request → 403 "Invalid origin" in the Network tab / Vercel function logs). Rather than set it per environment, derive the URL from each request:
  1. **Scalar**: `BASE_URL` was a quick fix for the API reference sending requests to `http://localhost` (no `:3000`). Cause: Nitro's `/_openapi.json` builds `servers[0].url` from the request origin, and Scalar fetches the spec during SSR through an internal request that lacks the real host/port. `nuxt.config.ts`'s `scalar.servers` override is evaluated at build time, so it also bakes one URL into each build. Fix: set `scalar.servers` to `[{ url: "/" }]` — a relative server URL, which Scalar resolves against `baseServerURL` (its component sets that from `useRequestURL().origin`, correct in the browser, port included). Verify in dev that "Try it" requests go to `http://localhost:3000/api/…`, and on Vercel to the deployment's domain.
  2. **Better Auth** (`server/utils/auth.ts`): replace `baseURL: process.env.BASE_URL` with its dynamic config, resolved per request against an allowlist: `baseURL: { allowedHosts: [...], protocol: … }` (type `DynamicBaseURLConfig` in `@better-auth/core`). Build `allowedHosts` from trusted sources: `localhost:*` in dev, and on Vercel the system env vars `VERCEL_PROJECT_PRODUCTION_URL`, `VERCEL_URL`, `VERCEL_BRANCH_URL` (plus a custom domain if one is added); avoid a blanket `*.vercel.app`, which would accept any Vercel app's host. `protocol: "https"` in production, `"http"` in dev. Check that sign-in/sign-up, session cookies, and `trustedOrigins` behave on localhost, a preview URL, and production; keep this in mind for emailed links later (`EMAIL_API_KEY` is configured but unused).
  3. **Remove the variable everywhere**: `.env.example`, the local `.env`, and Vercel's env vars. Better Auth also reads `BASE_URL` (and `BETTER_AUTH_URL`) from the environment on its own, so a leftover value would still take effect. The auth client (`app/utils/auth-client.ts`) already uses the current origin.
  4. While on Vercel, also confirm `BETTER_AUTH_SECRET` is set, `DATABASE_URL` points at the database your account is in, and that database has all migrations (`0006_sheet_system_groundwork` is new). Document the deployment env vars in README/CLAUDE.md.
