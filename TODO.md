- **TypeBox-based OpenAPI generation** · chore · needs decision: which approach
  Generate the OpenAPI request schemas from the TypeBox schemas in `server/utils/api-schemas.ts` instead of writing them by hand in each route's `defineRouteMeta`. Worth doing eventually: today every request body is described twice, and the two drift.

- **Content removal requests: legal takedowns and good-faith removals** · feature · needs decision: the policy wording (team, with legal review), who handles requests, and how a removal is recorded
  From the user (2026-10-05). Two kinds of request, both needing a written process and admin tools:
  - **Legal (DMCA and similar):** a rightsholder asks to remove content, either something we published by mistake or, more likely, something a community user uploaded. The aim is to be responsible for user-generated content only if we fail to act on a valid notice, as the DMCA safe harbor allows. That needs, at least: a designated agent registered with the US Copyright Office and a contact address on the site; a takedown process (receive notice, remove or disable access quickly, tell the uploader); a counter-notice process; a repeat-infringer policy; and terms of service that say all this. Have a lawyer check the requirements; the policy and terms text are team copy, not agent-written.
  - **Good-faith removals:** a publisher or author asks us to take down content that is openly licensed on paper (e.g. Pathfinder 2e under ORC), for example because they object to the site using AI in its development. We have no legal duty here but want good relations with the TTRPG community, so the default is to honor reasonable requests. The same goes for a data source we use and credit (see "Data sources and import scripts for official content"): if it objects, we stop using it and find another source.
  - Tools: the `resource` table already has `isAdminHidden`, `moderationReason`, `moderatedAt`, and `moderatedByUserId`, and access rules already hide admin-hidden resources (`getResourceAccess`), but nothing sets them yet. Add site-admin actions to hide and restore a resource with a reason, show the owner that it was removed and why, and keep a record of requests and what was done. Official content removed this way should also leave the import scripts, so a re-import doesn't bring it back.
  - Add a way to reach us about removals to the credits on official system pages (the credits themselves come with each system; see "Data sources and import scripts for official content").
